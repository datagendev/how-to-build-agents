how I create and use /agent in Claude Code. 

I typically take 4 steps: 
1) register , 2)develop, 3) update 4) test

1. Register: register agent by typing /agent -> almost always project -> almost always all tools -> generated by Claude -> briefly describe the scope -> create 

One of the caveat I found(in current Claude Code v. 2.1.29 )  is if you use /agent and generate your agent prompt using claude, it does not seem to fully explore your context in repo and tools you have and tend to be hallucinating. 

so unless its something super simple, I typically do develop next.  

2. Develop : /clear to clear context(so you have room). then manually breakdown the tasks and let CC complete in normal mode. like if I want to create a heyreach-review agent. I will exit /agent. and tell it to start by getting heyreach messages, then save them to @linkedin/conversations , then ask  it to review for me, tell me what I did right and what I did wrong. Sometime I also just give it a goal and let it grind.  but b/c now the main agent has full visibility of your context and can easily plan with you and see where it breaks or get confused, its much easier to craft the right *trace* of actions. and we can use this trace to "update" your agent. 

3. Update: Once you have the action trace, ask Claude Code to summarize what we did and update agent description in @.claude/agents/hey-reach-review.md  in step-by-step manner 

4. Test: /clear again(important so you can remove your previous trace dependency) . and ask CC to finish the {task} using {agent} . and see how it goes. 

An optional but useful practice I found is using /skill as much as possible in your agent. Overall I treat agent for job-to-be-done(main script), and skill for capability(library of function)

Using skills in agent brings 1) modularity and 2) tight test loop. Like I have a meeting summary agent. and this agent contains summary skill and report skill, along with some update tools.  Say if I want to optimize my summary results, I don't need to go e2e for the whole agent but can just focus on summary skill. Much faster feedback loop and all agents depend on it gets
 updated.  

Disclaimer: I am expecting some dramatic change for step.2 in terms of how to prompt agent to develop agent. for now, this type of workflow instruction is still helpful. but I also see people start to migrating into "goal defining" prompt rather than "instruction defining" to fully leverage model's knowledge and intelligence.
